# codex-kit — 시험 당일 가이드

외워야 할 건 두 줄뿐입니다.

    git clone https://github.com/bjun7595-ops/my-codex-kit.git ~/kit
    cat ~/kit/README.md

나머지는 이 문서를 보고 그대로 따라 치면 됩니다.


## 0. 과제 시작 직후 (0–15분)

- 과제 README.md를 직접 끝까지 읽는다.
- 필수 조건과 제출물(파일명, 위치)을 메모한다.
- 애매한 점은 추측하지 말고 메신저의 업무 담당자에게 묻는다.
- 화면 사용법은 Cofa Helper, 오류는 "문제 신고".


## 1. 준비 명령 (15–30분)

터미널 앞부분이 ~/workspace $ 인지 먼저 확인한다.

    ls

목록에 AGENTS.md가 없으면:

    cp ~/kit/AGENTS.md ./

AGENTS.md가 이미 있으면 복사하지 말고, 2단계에서 Codex에게 이렇게 요청한다.

    ~/kit/AGENTS.md 내용을 기존 AGENTS.md에 겹치지 않게 추가해줘

시작 상태를 기록한다. (git status가 에러 없이 나오면 git init은 생략)

    git status
    git init
    git add .
    git commit -m "초기 상태"

터미널 탭을 하나 더 열어서(+ 버튼) 이 문서를 띄워 둔다.

    cat ~/kit/README.md

원래 탭에서 Codex를 실행한다.

    codex

Codex 안에서 /status 로 모델을 확인한다. 권장: 6.1 Sol / 5.6 Terra / 6.0 Luna. Astra 금지.


## 2. Codex에게 보낼 문장 — 시작

    README.md를 읽고 필수 조건과 제출물을 목록으로 정리해줘. 애매한 부분도 따로 알려줘.

    ~/kit/templates/PLAN.md 양식으로 README 기반 PLAN.md를 작업 폴더에 만들어줘. 과제가 파일명을 정했으면 그 이름으로.

    ~/kit/templates/WORKLOG.md 양식으로 빈 WORKLOG.md도 만들어줘. 과제가 파일명을 정했으면 그 이름으로.

만들어진 PLAN.md는 에디터에서 직접 열어 읽고, 틀린 부분은 고치라고 한다.


## 3. 구현 반복 (30–130분) — 기능 하나씩

① 맡기기

    PLAN.md의 작업 1번만 구현하고, 테스트도 작성해서 실행해줘.

② 승인 요청이 오면 명령 내용을 읽고 y 또는 n. 같은 요청을 반복하지 않는다.

③ 테스트가 실패하면

    테스트가 실패했어. 원인을 먼저 설명하고 고쳐줘.

④ 이해 안 되는 코드가 있으면 (서술형 대비)

    방금 만든 코드 구조를 쉽게 설명해줘.

⑤ 다른 탭에서 확인 (10초)

    git status
    git log --oneline

- "nothing to commit" → 커밋 완료. 다음 작업으로.
- 파일 목록이 남아 있음 → Codex에게 "커밋해줘".
- 화면이 멈춘 것 같으면 q 를 누른다.

⑥ 다음 작업: "PLAN.md의 작업 2번만 구현하고..." 반복

버그는 증상을 구체적으로 말한다.

    추가 버튼을 누르면 목록에 안 나타나. 원인 찾아서 고쳐줘.


## 4. 최종 점검 (130–160분)

서버 띄우기:

    서버를 0.0.0.0으로 실행하고 포트 번호 알려줘.

왼쪽 Browser 도구에서:
1. PORT 칸에 터미널에 나온 포트 번호
2. URL 칸은 / 그대로
3. 오른쪽 원형 화살표 클릭
4. 화면이 뜨면 버튼, 입력, 이동을 직접 눌러 본다

서버가 돌고 있는 터미널 탭은 절대 닫지 않는다.
안 뜨면: 터미널 에러 → 포트 번호 → 0.0.0.0 → 경로 순서로 확인.

필수 조건 점검:

    ~/kit/skills/check-requirements/SKILL.md를 읽고 그대로 필수 조건을 점검해줘.

❌ 미충족 → ⚠️ 확인 필요 순서로 고친다. 새 기능 추가보다 우선.


## 5. 문서 마무리 (160–170분)

    ~/kit/skills/write-worklog/SKILL.md를 읽고 그대로 작업 기록을 정리해줘.

완성된 문서를 직접 읽는다. 판단 근거, 검증 결과, 남은 한계, 참고 출처가 있는지 확인.

서술형 대비:

    이 프로젝트 전체 구조, 데이터 흐름, 내가 내린 주요 결정을 5분 안에 읽을 수 있게 요약해줘.


## 6. 제출 (170분~, 종료 10분 전 시작)

1. 다른 탭에서 git status → 커밋 안 된 게 없는지
2. 에디터 탭마다 "저장됨" 확인 (파일명 옆 U/M 표시 확인)
3. 상단 "제출하고 문제풀기" → 미리보기 확인
4. "제출물 확정하고 문제풀기" → 확정 후 수정 불가


## 7. 후속 서술형 (30분)

- 6문항, 문항당 5분. AI 금지, 복사·붙여넣기 불가, 이전 문항으로 못 돌아감.
- 내 제출물과 작업 기록 기준으로 질문이 나온다.
- 질문의 전제가 실제 구현과 다르면, 차이를 밝히고 실제로 한 작업을 설명한다.
- 끝나면 완료 화면에서 제출 ID, 시각, 파일 수 확인 후 퇴장.


## 절대 하지 말 것

- 외부 브라우저로 GitHub, 검색 사이트 접속
- git push
- Codex 업데이트 (업데이트 메시지가 떠도 무시)
- Astra 모델, 다른 AI 도구 연결, API 키가 필요한 도구 설치
- 서버 돌아가는 터미널 탭 닫기
- 마지막에 외부 코드로 결과물 통째로 바꾸기

- skills/check-requirements/SKILL.md — 필수 조건 점검
- skills/write-worklog/SKILL.md — 작업 기록 정리
- templates/PLAN.md, templates/WORKLOG.md — 문서 양식
