# 담당자 질문

담당자 확인이 과제의 일부라면, "확인하고 설계에 반영했다"는 흔적(`docs/questions.md` + 코드·문서 반영)이 평가된다.
담당자는 구현 방법·정답을 주지 않는다 → **업무 의미와 기준값**을 묻는다.

## 에이전트가 할 일

1. 질문 후보를 뽑고 우선순위를 매긴다: **결과의 정합성을 바꾸는 것** > 최적화 기준값 > 화면 표시 방식.
2. 응시자에게 보낼 **메시지 초안**을 보여 준다(에이전트가 직접 보내지 않는다).
3. 답이 오면 `docs/questions.md` 기록 → `docs/decisions.md` 결정 추가([가정] 해제) → 코드·검증 규칙·문서 수정.
4. 기다리는 동안 멈추지 않는다. 규칙을 더 엄격하게 지키는 쪽으로 가정하고 진행.

## 질문 유형

- **데이터 의미**: 문서에 없는 값, 날짜·시각의 귀속, 두 파일의 불일치, 범위 밖 행이 각각 업무상 무엇인지.
- **품질 기준값**: 이용자가 감수할 수 있는 거리·대기·이동·우회·변동의 한도, 같은 대상이 날마다 바뀌어도 되는지, 기존 상태 유지 선호.
- **운영 조건**: 함께 묶어도 되는 대상의 범위(시간대·소속), 예외 처리, 화면의 "현재" 기준(실제 시각 vs 지정 시각).
- **우선순위**: 효율과 편의가 충돌할 때 무엇을 먼저 보는지.

## 작성 원칙

- 한 번에 1~3개, 번호. **관찰 수치(건수·예시)를 먼저**.
- 예/아니오나 숫자로 답할 수 있게. "어떻게 하면 좋을까요?" 금지.
- 업무 메신저 톤, 짧게.

```
안녕하세요, 데이터 확인 중 두 가지 여쭙니다.
1) ○○ 열에 문서에 없는 값 A(123건), B(45건)가 있습니다. 둘 다 그날 대상에서 제외하면 될까요?
2) 이용자가 받아들일 수 있는 △△의 한도가 있을까요? (예: 기준보다 N분 이내)
```

## 반영 체크
- [ ] 기록(questions, decisions)
- [ ] 검증 규칙(허용값, 오류/경고 정책)
- [ ] 엔진 파라미터 기본값(상수가 아니라 설정값)
- [ ] 실행 안내 문서의 "설계 기준"·"확인 사항"
