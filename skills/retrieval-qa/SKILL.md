# 문서 질의응답 기능

에이전트가 참고 문서를 찾는 일은 `AGENTS.md` 4-1절로 충분하다. 이 스킬은 **서비스 기능으로** 검색·답변을 만들 때만.

## 순서 (단순한 것부터 동작시키고 올린다)

1. **적재**: 원본 → 텍스트(문서 형식별 변환), 문서 ID·제목·쪽/절 정보 보존. 변환 실패 문서는 목록으로 보고.
2. **분할**: 제목·절 단위가 기본. 너무 길면 문단 단위로 자르고 앞뒤 일부 겹침. 각 조각에 (문서, 제목 경로, 위치) 메타데이터.
3. **키워드 검색 먼저**: SQLite 전문 검색이나 BM25. 모델·외부 API 없이 동작. 여기까지로 시연 가능한 상태를 먼저 만든다.
4. **(필요 시) 의미 검색**: 표현이 달라도 찾아야 하면 임베딩 추가, 키워드 결과와 합쳐 순위(혼합). 응시 환경에서 모델·API를 쓸 수 있는지 먼저 확인.
5. **답변**: 상위 조각만 근거로 답하고 **출처(문서·제목·위치)를 함께** 보여 준다. 근거가 없으면 "문서에서 찾지 못함"이라고 답한다(지어내지 않기).
6. **데이터 교체**: 문서 묶음을 바꾸면 색인을 다시 만들고, 색인 버전과 결과를 묶어 오래된 색인 결과를 새 결과처럼 보이지 않게(`dataset-lifecycle`과 같은 원칙).

## 품질 확인

- 질문 10개 내외와 "정답이 있는 위치"를 직접 만들어, 상위 N개 안에 그 위치가 나오는 비율을 잰다.
- 동의어·띄어쓰기·약어 질문을 섞는다. 실패한 질문은 분할 단위나 검색 방식 조정의 근거로 기록.
- 화면: 질문 입력 → 답변 + 출처 목록(클릭 시 원문 구간) + 검색된 조각 확인(운영자용).

## 함정

- 문서 전체를 한 번에 모델에 넣는 방식은 느리고 비싸며 출처가 흐려진다.
- 표·목록이 변환 중 깨지는지 확인.
- 권한이 다른 문서(역할별 열람 범위)가 있으면 검색 단계에서 걸러야 한다.
