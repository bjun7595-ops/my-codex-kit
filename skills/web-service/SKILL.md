# 웹 서비스 골격

## 기본 구성 (지시문이 자유일 때)

- 서버: 파이썬 웹 프레임워크(예: FastAPI) 또는 응시자가 익숙한 것. **`0.0.0.0` 바인딩**, 포트는 설정값, 기동 시 실제 주소 출력.
- DB: SQLite 파일(경로는 설정값). 기동 시 테이블이 없으면 생성 → 초기 계정 → 초기 데이터셋 적용(빈 DB에서 바로 쓸 수 있게).
- 프론트: 빌드 단계 없는 정적 HTML + JS(fetch). 번들러 설정에 시간 쓰지 않는다.
- 폴더: `app/`(서버), `app/engine/`(순수 계산), `app/datasets/`(검증·적재), `app/static/`(화면), `tools/`(검증기·데이터 생성), `data/`.

## 로그인과 역할

- 서비스 안에서 구현. 세션 쿠키(서명), 비밀번호는 해시(표준 라이브러리 PBKDF2 정도면 충분).
- 역할별 의존성/미들웨어 하나로 검사: 미로그인 401, 권한 없음 403.
- 이용자 역할 API는 **세션의 본인 ID만** 쓴다. 다른 사람 ID를 파라미터로 받지 않는다.
- 이용자 계정: 데이터의 사람 ID + 초기 비밀번호(설정값). 데이터셋이 바뀌면 신규 ID만 추가.
- 초기 비밀번호를 코드·화면에 박지 않는다. 실행 안내에 "설정값 이름과 예시값"으로 적는다.
- 채점자가 두 역할로 각각 들어가 볼 수 있도록 실행 안내에 계정 예시를 명확히.

## 화면

- 역할 A(운영): 데이터셋 관리, 조건(파라미터) 변경, 생성 실행, 전체 결과, 지표·시나리오 비교, 내보내기.
- 역할 B(이용): 날짜·조건 선택 → 본인 결과(일정·위치·상태), 시각화.
- 상태 배지: 현재 데이터셋, 결과 최신/재계산 필요.
- 긴 작업: 수 초면 동기 처리, 30초 넘으면 백그라운드 + 상태 폴링.
- 오류 응답 형식 통일(`{"detail": 사람이 읽는 메시지}`), 화면은 그대로 표시.

## 결과 내보내기 (파일 선택·저장창 없이)

- 생성 시점에 출력 스키마 변환 → 서버 쪽 내보내기 폴더에 파일 저장 → 경로 반환.
- `GET` API가 JSON을 **본문으로** 반환(첨부 헤더 없이).
- 화면: JSON 미리보기 + [복사] 버튼 + 저장 경로 표시.
- `<input type="file">`, 저장 대화상자 API, 첨부 다운로드 헤더를 쓰지 않는다.

## 설정값

- 설정은 환경변수 또는 설정 파일 한 곳에서 읽는다. 지시문이 환경변수·예시 파일을 요구하면 `deploy-if-required`.
- 업무 파라미터 기본값(정원, 여유 시간 등)도 설정 한 곳에. 운영자 화면에서 바꾼 값은 생성 요청 파라미터로 엔진에 전달하고 결과와 함께 저장.
