# 최적화 전략

## 1. 유형 판별 (5분)

지시문에서 "무엇을 정해야 하는가"를 동사로 뽑는다. 여러 단계가 섞여 있으면 단계별로 판별한다.

| 결정해야 하는 것 | 유형 | 스킬 |
|---|---|---|
| 지점들을 **어떤 순서로** 돌지, 차량·인원이 **어느 경로**로 갈지 | 노선·순회 | `routing-problems` |
| 사람·작업·물건을 **어디(누구)에** 붙일지, 짝을 지을지 | 배정·매칭 | `assignment-problems` |
| **언제** 할지, 근무·수업·작업을 시간 칸에 놓을지 | 일정·교대 | `scheduling-problems` |
| 후보 중 **어떤 것을 고를지**(거점·설비), 용량 안에 **무엇을 담을지** | 선정·적재 | `selection-packing` |

흔한 복합형: "거점 선정 → 배정 → 노선" (선정·적재 → 배정 → 노선), "인력 배정 + 근무 시간" (배정 + 일정).
**앞 단계 결과를 고정하고 다음 단계를 푸는 순차 분해**가 3시간 안에서는 가장 안전하다. 분해했다는 사실과 이유를 문서에 쓴다.

## 2. 제약을 세 층으로

| 층 | 무엇 | 다루는 법 |
|---|---|---|
| 하드 규칙 | 지시문이 정한 것. 하나라도 어기면 실패 | 알고리즘이 **구조적으로** 못 어기게 + 독립 검증기 |
| 품질 제약 | 담당자에게 확인할 기준값(대기·이동·거리·공정성 한도) | 파라미터. 못 지킨 경우를 **지표로 보고** |
| 목적 | 남은 자유도에서 좋게 만들 것(자원 수, 비용, 시간, 만족도) | 사전식 순서로 최소화 |

가중합(α·비용 + β·시간)은 가중치를 설명하기 어렵다. **사전식**이 방어하기 쉽다:
`규칙 위반 0 → 품질 제약 충족 → 1순위 목적(대개 자원 수) → 2순위(이용자 부담) → 3순위(형평·안정성)`

## 3. 품질 제약은 "상대 기준"이 대개 낫다

- 절대 상한(예: 이동 ≤ N분)은 원래부터 먼/긴 대상에게 실행 불가능하거나, 묶음을 막아 자원이 폭증한다.
- **상대 기준**(예: "직접 이동 대비 추가 시간 ≤ N분", "희망 대비 차이 ≤ N")은 모두에게 공평하고 자원 효율도 좋다.
- 두 기준을 다 파라미터로 두고 시나리오 비교로 고른다. 숫자는 담당자 답이 최선, 없으면 곡선의 꺾이는 지점.

## 4. 단계적 구현 (시간 상자 안에서)

1. **실행 가능한 최소 해** — 가장 단순한 규칙 기반(가까운 것, 이른 것, 여유 있는 것 먼저). 하드 규칙 100% 충족이 목표.
2. **구성 휴리스틱** — 유형 스킬의 표준 기법.
3. **지역 개선** — 이동·교환·재삽입을 "개선될 때만 채택". 시간·반복 상한.
4. (여유 시) 비교 실험 — 다른 설정·기법과 지표 비교.
각 단계가 끝날 때마다 검증기 통과를 확인하고 커밋한다. 개선 단계가 실패해도 1·2단계 결과로 제출할 수 있게.

## 5. 지표와 시나리오 비교 (화면·문서에 넣는다)

- 자원 지표: 사용 자원 수, 이용률(정원 대비), 총비용·총시간
- 이용자 지표: 평균·95분위·최대(대기, 이동, 거리, 희망 불일치)
- 형평 지표: 사람·그룹 간 편차(최대−최소, 표준편차)
- 예외: 품질 제약을 못 지킨 건수와 사유
2~4개 시나리오(효율 우선 / 균형 / 편의 우선)를 같은 지표로 표에 놓고, **채택값과 이유**를 쓴다.
같은 입력의 결과 캐시(입력 키 = 관련 데이터의 정렬된 튜플)로 재계산을 빠르게.

## 6. 성능 감각

- 수천 개 대상 × 수십 날짜 규모면 순수 휴리스틱으로 수 초 안에 끝나야 한다. 1분 넘으면 구조를 의심(중복 계산, 전체 재계산).
- 외부 솔버 패키지는 설치 실패·시간 초과 위험. 기본 엔진은 직접 작성한 휴리스틱, 솔버는 비교 실험용으로만.
