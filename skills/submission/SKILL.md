# 제출

## 1. 시연 확인 (응시자와 함께)

`PLAN.md`의 시연 시나리오를 처음부터 끝까지 실제로 돌린다. 막히는 단계가 있으면 문서보다 그것을 먼저 고친다.
응시자가 "이대로 제출"이라고 확인하면 다음 단계.

## 2. 양식 확인

지시문에 제출 문서 양식(파일명, 제목, 질문)이 있으면 **그대로** 쓴다. 아래 3·4절은 내용 채우기용 목록이고, 양식과 충돌하면 양식이 우선.

## 3. 실행 안내 문서

- 기술 스택, 복붙 가능한 실행 명령, 미리보기 경로
- 역할별 접속 방법과 계정(설정값 이름 + 예시값)
- 데이터 준비·선택·적용, 오류 확인 **절차**(결과를 미리 적지 않는다), 변형 데이터 재현 방법
- 결과 내보내기 방법과 위치
- 설계 기준(하드 규칙 / 품질 기준 / 목적 순서), 방식(단계), 시나리오 비교 표, 담당자 확인 사항, [가정], 한계

## 4. AI 협업 문서

`PLAN.md`, `docs/decisions.md`, `docs/questions.md`, git 로그에서 **구체적 사례**를 뽑는다:
역할 분담과 맡긴 방식(완료 조건), 컨텍스트 설계 이유, 검증 방법, AI 결과를 바로잡은 사례, 다시 한다면.

## 5. 마지막 점검 (5분)

- `git status`, 마지막 커밋. 지시문 파일 변경 없음(`git diff --stat -- <지시문 파일>`).
- 금지 UI 검색: 파일 입력, 저장 대화상자, 첨부 다운로드 헤더.
- 내보낸 파일로 검증기 → 위반 0.
- 필수 파일(실행 안내, AI 협업 문서, 변형 데이터 또는 생성 레시피·스크립트, 컨텍스트 파일) 존재.
- 서버가 떠 있는 상태로 미리보기에서 핵심 화면 한 번 더.
