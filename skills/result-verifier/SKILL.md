# 독립 결과 검증기

출력 스키마가 지정된 과제는 그 파일로 규칙 준수를 검증할 가능성이 높다. 같은 일을 먼저 한다.

## 원칙

- **엔진 코드를 import 하지 않는다.** 입력 데이터 파일과 내보낸 결과 파일만 읽는다(같은 버그 공유 방지).
- **내보낸 파일 그대로** 검증한다. 변환 왕복에서 시각·날짜·ID가 틀어지는 경우가 많다.
- **규칙 하나 = 검사 함수 하나.** 요구사항 매트릭스의 "하드 규칙" 행과 1:1 대응. 함수 이름에 규칙 번호(R3 등).
- 규칙 함수 하나가 예외로 죽어도 나머지는 돈다(각 함수를 try로 감싸 "검사 실패"로 보고).
- 출력: 위반(오류) / 경고(품질 기준) / 정보, 건수와 앞 N건 예시. 위반이 있으면 종료 코드 1.
- 파라미터(정원, 여유 시간, 기간 등)는 **생성 때와 같은 값**을 인자로 받는다.

## 구조 (작업 공간에서 작성, 짧게)

1. `load_inputs(data_dir)` — 필요한 파일만 읽어 dict로.
2. `load_result(path)` — 출력 스키마 → 내부 정규 형식(검사하기 쉬운 평평한 구조). 스키마가 바뀌면 이 함수만 고친다.
3. `RULES = [check_r1, check_r2, ...]` — 각 함수는 (inputs, result, params) → 이슈 목록.
4. `main` — 실행·요약 출력·종료 코드.

## 유형별 단골 검사

- 공통: 대상 전원이 정확히 필요한 횟수만큼 배정(누락·중복), 비대상 미배정, 허용된 ID만 사용, 기간·날짜 범위, 스키마 필수 필드.
- 용량: 칸·차량·자원별 인원 ≤ 정원(설정값과 결과 내 정원 둘 다).
- 시간: 기준 시각 여유(이전·이후), 연속 이벤트 시각차 ≥ 지정 소요시간, 자원별 겹침, 휴식, 자정 넘김.
- 소속·자격: 대상의 소속·자격과 칸의 요구 일치.
- 품질(경고): 거리·대기·우회 한도 초과 건수.

## 자체 테스트 (2분)

정상 결과를 일부러 망가뜨려 잡히는지 본다: 대상 1명 삭제, 비대상 추가, 시각을 크게 당기기, 정원 초과, 없는 ID.
하나라도 안 잡히면 그 규칙 검사가 비어 있는 것이다.
