# 데이터 점검

## 방법

작은 점검 스크립트를 **이 작업 공간에서** 작성해 `scratch/`에 두고 돌린다(표준 라이브러리 csv로 충분, 몇 초 안에).
결과는 요약만 출력한다(파일 전체 출력 금지). 점검 항목:

1. 파일별 행 수, 열 목록, 열 개수 불일치 행, 인코딩(BOM) 문제.
2. 열마다 빈 값 수, 고유값 수, 추정 형식(정수/실수/날짜/시각/불리언/텍스트), 형식 불일치 건수.
3. 고유값이 적은 열(≈30개 이하)은 **값 분포 전체** — 문서에 없는 범주값이 여기서 드러난다.
4. ID 열의 교차 파일 참조: 정의 파일(첫 열이 ID이고 값이 고유)을 찾아 다른 파일의 같은 이름 열을 대조.
   한 열에 여러 종류 ID가 섞이는 것이 문서상 허용인지 확인.
5. 키 후보: 수치가 아닌 열을 앞에서부터 더해 가며 행을 고유하게 만드는 최소 조합 → 중복 행 확인.
6. 날짜 열: 범위, 요일 분포(주말 포함 여부), 범위 안 빠진 날짜.
7. 시각 열: 형식 오류, 시작 > 종료(자정 넘김).
8. 좌표 열: 범위, 숫자 아님.
9. 쌍 테이블(from, to, 값): 기대 쌍 수 = n×(n−1) 대비 누락, 대칭 여부(A→B와 B→A 차이).
10. 같은 속성이 두 파일에 있으면(마스터 vs 날짜별) 불일치 건수.

## BRIEF.md 보강 (점검 후)

첫 브리핑(`task-kickoff` A)의 8·10절을 점검 결과로 보강한다. 숫자는 점검 스크립트 결과에서만(추측 금지).

- 파일 표의 행 수·키를 확정값으로, 관계에 1:N과 참조 불가 건수.
- 시간 구조: 날짜·시각 열의 의미, 기간, 자정 넘김, 주말 포함 여부.
- **예시 한 건 따라가기**: 대상 하나를 골라 여러 파일에서 그 대상의 행을 이어 붙여 사람 말로 설명. 데이터가 어떻게 엮이는지 가장 빨리 이해된다.
- 이상한 점(건수 포함)과 담당자 질문 번호.

응시자가 데이터에 대해 물으면 스크립트로 확인해서 답하고 BRIEF.md에 반영한다.

## 관찰 → 행동

| 관찰 | 행동 |
|---|---|
| 문서에 없는 범주값 | 담당자 질문, 확인 전까지 보수적 처리, 검증 정책(오류/경고) 결정 |
| 참조 불가 ID | 건수·예시 기록, 원본 문제인지 범위 차이인지 질문 |
| 마스터와 날짜별 기록 불일치 | 날짜별 우선이 자연스러움, 확인 |
| 주말·범위 밖 날짜 | 계획 대상 규칙과 대조, 제외 + 경고 |
| 자정 넘김 | 기준일 귀속 규칙 확인 |
| 비대칭 쌍 | 방향별 계산 필수 |
| 실적·관측 데이터에 상한(정원 등)에 닿은 값 | 잘린 값 → 수요로 쓰지 않음 |

중요한 관찰은 `docs/decisions.md` 또는 `docs/questions.md`로 옮긴다. 원본 점검 출력은 `scratch/`에만.

## 원본이 검증에 실패하면

제공 원본 데이터가 내가 만든 검증 규칙에 걸리면 **규칙이 틀린 것**이다(예: 문서에 없는 상태값).
담당자 확인 → 허용값·정책 수정 → 원본이 통과해야 초기 데이터가 된다.
