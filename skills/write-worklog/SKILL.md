# 작업 기록 정리

## 순서

1. 사실 자료를 먼저 모은다.
   - `git log --oneline`과 주요 diff
   - 테스트 실행 결과 (직접 다시 실행해서 확인)
   - 기존 계획 문서와 작업 기록
2. 아래 항목을 채운다. 파일명과 양식은 과제 안내가 있으면 그것을 따른다.
   - 목표: 과제가 요구한 것 한두 줄
   - 결정과 근거: 무엇을 선택했고, 다른 방법 대신 왜 그렇게 했는지
   - 진행 과정: 커밋 순서대로 무엇을 만들었는지
   - 검증 결과: 실제로 실행한 명령과 결과 (예: 테스트 12개 통과, 미리보기에서 추가 버튼 동작 확인)
   - 남은 한계: 처리하지 못한 상황, 알려진 문제
   - 참고 출처: 사용한 외부 코드·라이브러리·저장소

## 주의
- 확인하지 않은 내용을 사실처럼 쓰지 않는다. 확인하지 못했으면 "미확인"이라고 쓴다.
- 과장하지 않는다. 안 된 것은 한계에 솔직하게 적는다.
